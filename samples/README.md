# Sample legacy apps

Small, hand-written synthetic applications used to test every phase. Each folder has its own `audit.yaml`, optional `audit-inputs/`, and an `expected.yaml` with the exact counts the scanner must produce. Keep each under ~2,000 lines; they need to be realistic in structure, not in business logic.

All seven exist (`legacy-layout-app` added with the component-classification change, `angular-node-app` with the Angular/Node change, `web-services-app` with the web services change). `tests/test_samples.py` scans each one and compares the result with its `expected.yaml`: inventory and components (phase 1), then headline counts, services, screens, integrations, batch jobs and unresolved references (phase 2), then findings by rule and severity, PostgreSQL grades, complexity bands, vulnerable and end-of-life libraries and upgrade actions (phase 3, `assessment:`). When an analyzer change moves a number, check the new value by hand before updating `expected.yaml`.

| Sample | Technologies | What it exercises |
| --- | --- | --- |
| `struts-oracle-app/` | Struts 1, JSP, servlets, JDBC, Oracle SQL (NVL, ROWNUM, CONNECT BY, `(+)`), Log4j 1.x, Commons-Collections 3 in `WEB-INF/lib`, SOAP client (Axis 1), Ant build | Services, screens, partials, SQL grading, undeclared jars, EOL/vulnerable libraries |
| `spring-mvc-batch-app/` | Spring 4 XML config + annotations, Spring MVC + JSP, JdbcTemplate, Hibernate HQL, MyBatis mapper, Spring Batch, JmsTemplate to IBM MQ, Spring Security LDAP, Maven multi-module | Spring analyzers, bean graph, batch jobs, MQ integrations, `javax` → Jakarta signals, BOM-managed upgrades |
| `c-proc-batch/` | C, Pro*C (cursors, host variables), ksh scripts calling the binaries, `CFTUTIL SEND`, sqlplus, Makefile, MQI calls | C/Pro*C analyzers, scripts → programs linking, CFT and MQ integrations |
| `cobol-cics-db2/` | COBOL programs + copybooks, CICS transactions + BMS maps, DB2 EXEC SQL, JCL jobs | COBOL/CICS screens and services, copybook resolution, JCL batch chains, DB2 grading |
| `legacy-layout-app/` | No top-level build: an Eclipse Struts project (`.project`, `.classpath`, compiled `bin/`), a batch of Java + ksh + properties in plain folders (with a stray `classes/`), a Pro*C batch with its generated `.c`, `obj/` and `Makefile.aix`, a shared `config/`, deploy scripts; no scheduler export | Build output left out, layout-based components (container `apps/`, parts folders), `config` type, roles, one unscheduled batch per batch component |
| `maven-multimodule-app/` | Maven parent and aggregator (packaging pom) with jar, war and ear modules, a module only in a profile, a nested parent of two batch modules started by ksh scripts, a shared `config/`, an `ops/batch/` folder of several plain-folder batches with a shared `common/`; no scheduler export | Parents and aggregators as groups (not components), Maven modules as components, batch folder split, one batch per entry point (decisions 166-168) |
| `angular-node-app/` | Angular and AngularJS front ends, Express and NestJS APIs, TypeORM/Prisma/raw SQL, node-cron jobs, npm lock files, app and web server descriptors | Front end and API components, SPA screens, front end to API calls, servers with versions and end of life |
| `web-services-app/` | JAX-WS + CXF with WSDL, JAX-RS on Jersey, Spring REST controller, Axis 1 (`server-config.wsdd`, `.jws`), RestTemplate, Feign with a `${...}` URL, a generated JAX-WS client with its WSDL, libcurl and gSOAP calls from C | Web services offered and called (REST and SOAP), operations, WSDL contracts attached to their service, one integration per called system |
| `*/audit-inputs/` fixtures | Autosys JIL (boxes, CMD jobs, conditions s()/f()/d(), file watcher) and MQSC in `spring-mvc-batch-app`; CFT partner/flow export and crontab in `c-proc-batch`; Oracle DDL in `struts-oracle-app` | Late inputs and re-run behaviour (`tests/test_linking_rerun.py` adds the JIL after a first scan) |

Dynamic SQL (built at run time) is in every language sample: `OrderDao.advancedSearch` (Java `StringBuffer` with conditional appends and a ternary) and `OrderDao` line 69 (a concatenated value) in `struts-oracle-app`; `InvoiceDao` (`ORDER BY` from a variable) and `PaymentMapper.xml` (MyBatis dynamic tags) in `spring-mvc-batch-app`; `purge_old` in `settle_load.pc` (`sprintf` table name + conditional `strcat`, then `PREPARE FROM :dyn_sql`) in `c-proc-batch`; `ORDRPT` `DETAIL-PARA` (`MOVE`/`STRING` with an optional region filter and a sort column, then `PREPARE FROM :WS-DYN-SQL`) in `cobol-cics-db2`.

Some references are deliberately missing so unresolved-reference reporting is exercised: `layout.jsp` (struts-oracle-app), `archive_usage.sh` (spring-mvc-batch-app) and `purge_logs.sh` (c-proc-batch).

Vulnerability results come from recorded reports in `audit-inputs/security/`: a Dependency-Check JSON report in `struts-oracle-app` (one entry matched by SHA-1, one with no vulnerabilities) and an OSV-Scanner JSON report in `spring-mvc-batch-app` (one package that is not in the inventory). The sample tests force both tools "not installed", so results never depend on the machine or the network.
