# Decisions

Decisions taken while planning. Newest last. These override `docs/plan.md` where they differ.

| # | Date | Decision | Reason |
| --- | --- | --- | --- |
| 1 | 2026-10-10 | Hybrid architecture: deterministic Python engine + Copilot agent + local GUI | Counts must be reproducible; AI only for interpretation |
| 2 | 2026-10-10 | No external LLM anywhere (no Vertex AI, no API calls). GUI hands off to Copilot Chat only | Client/organisation policy |
| 3 | 2026-10-10 | Autosys (JIL), IBM MQ and CFT are first-class analyzers, built in phase 2 | They appear in most of the team's applications |
| 4 | 2026-10-10 | Supplementary inputs (JIL, MQSC, CFT exports, DDL, crontab) arrive later and go in `audit-inputs/`; the tool must re-run any number of times and refresh reports | Team receives these exports after the code |
| 5 | 2026-10-10 | Branding is a config slot with a neutral default theme; corporate PPT template added later | Template exists but is not available yet |
| 6 | 2026-10-10 | Optional Git source: tool clones repo URLs itself into a cache; local folder stays the default | Analysts may not want to clone by hand |
| 7 | 2026-10-10 | Spring family (core, MVC, Web Flow, Boot 1–3, Batch, data access, Integration/JMS, Security) and Hibernate/MyBatis are in scope | Many legacy Java apps are older Spring |
| 8 | 2026-10-10 | Dependency management section: inventory + CycloneDX SBOM, OWASP Dependency-Check (OSV-Scanner optional), rule-based upgrade recommendations | Requested; security exposure is a migration driver |
| 9 | 2026-10-10 | Target versions: Java 25, Spring Boot 4.1 (Spring Framework 7, Jakarta EE 11), Angular 21 (TypeScript 5.9, Node 22/24), PostgreSQL — all configurable | Boot 4.0 OSS support ends 31 Dec 2026; Angular 21 requested |
| 10 | 2026-10-10 | The *audited* teams use GitHub Copilot in VS Code | Most analysts already have it |

## Open

- Typical estate size (LOC, number of apps): still open. Phase 6 used the default target, 2M LOC scanned in under 15 minutes on a laptop (decision 92, `docs/performance.md`).
- Angular 21 fixed, or "latest Angular LTS"? Default: 21, configurable.
- Further frameworks (EJB 2.x, JSF, GWT, Tapestry, .NET)? Default: EJB and JSF covered at the level in the plan; others not in scope.

## Phase 2 decisions

| # | Date | Decision | Reason |
| --- | --- | --- | --- |
| 24 | 2026-10-10 | Runtime dependency `sqlglot` (pinned to one major) parses SQL for type, tables, procedures and vendor features | Pure Python, many dialects (Oracle, DB2); one major keeps counts reproducible across installs |
| 25 | 2026-10-10 | Runtime dependencies `tree-sitter`, `tree-sitter-java`, `tree-sitter-c`, `tree-sitter-cpp` parse Java and C/C++ (decides the phase 1 open point #22: tree-sitter over `javalang`) | Error-tolerant (a broken file still yields facts plus an unparsed region), one library for Java and C/C++, Java 1.4–21 syntax, prebuilt wheels for Windows; `javalang` stops at Java 8 and fails on the first error |
| 26 | 2026-10-10 | COBOL, BMS, JCL, JIL, MQSC, CFT, shell, SQL scripts, JSP and config files are read with regular expressions over cleaned lines, not full grammars | These formats are line-oriented; the facts we count need statements, not a full parse tree |
| 27 | 2026-10-10 | Every Autosys/JCL/cron job except boxes and file watchers is also a service of kind `batch-job`; boxes are counted separately and never as jobs | A job is an entry point the migration must keep; a box only groups jobs |
| 28 | 2026-10-10 | A COBOL program that is only CALLed or LINKed by other programs is a sub-program, not a service; programs run by JCL or a scheduler, or owning a CICS transaction, stay. Edges to a pruned program point at its file | Counts the things a user or a scheduler can start, as the plan's service definition says |
| 29 | 2026-10-10 | A JSP/HTML page is a screen when navigation targets it (forward, render, submit, link) or a navigated tiles definition is the only one including it; a page that is only included is a partial; `.jspf` and tag files are always partials; an HTML page nothing targets is dropped, a JSP nothing targets stays a screen | Fragments and layouts would otherwise inflate screen counts; unreferenced JSPs are usually reached by URL |
| 30 | 2026-10-10 | Integrations are merged by (type, target). A definition (MQSC, CFT export) is not a usage (`usages: 0`, direction `defined`); MQ direction comes from producers and consumers; CFT export flows `*/IDF` fold into script usages with the same IDF and direction and give them the partner host and NSPART; transmission queues are not integrations; JMS queues are typed `MQ` | One row per real interface, with usages counted only where code uses it |
| 31 | 2026-10-10 | Libraries: internal Maven modules are not libraries; a jar known only by file name folds into the declared library with the same artifact and version; Maven versions are resolved through the parent chain after all poms are read | Avoids counting the same library twice and counting the application itself |
| 32 | 2026-10-10 | Tech-stack items are also derived from library coordinates; a versionless item folds into the single versioned item of the same name (kept separate when there are several versions) | Imports alone carry no version; guessing between versions would be wrong |
| 33 | 2026-10-10 | A service's `tables` and `external_calls` are what it reaches within 4 hops over calls/uses/invokes/runs/triggers/includes edges, from the service and its file | Bounded, deterministic reach; deeper chains are left to the agent with evidence |
| 34 | 2026-10-10 | A reference that cannot be resolved is an unresolved edge to `unresolved:<name>` plus an `unresolved-reference` finding (info); references through variables (`$BIN/x`, called by name in C) are linked if found but never reported | Missing code is a coverage gap to show, not an error; variable paths are too often outside the estate |
| 35 | 2026-10-10 | Component types are refined from what was found: web > online-mainframe > batch > cft; types from overrides or config are kept | Folder rules alone cannot tell a batch module from a web one |
| 36 | 2026-10-10 | The config analyzer leaves `audit-inputs/{autosys,mq,cft,crontab,ddl}` to their own analyzers, does not read hosts or queues from Spring `<beans>` XML (the Spring analyzer does), and treats message bundles, placeholders and values with spaces as non-credentials | Each fact is found once, by the analyzer that understands it; avoids false credential findings |
| 37 | 2026-10-10 | A Java string with no SQL call site counts as SQL only when it has upper-case `SELECT ... FROM` or SQL punctuation/keywords (`*`, `,`, `=`, `?`, `WHERE`, `JOIN`, ...) | UI captions such as "Select a customer from the list" are not SQL |
| 38 | 2026-10-10 | An analyzer that crashes on a file records an `analyzer-error` finding (low) and a coverage gap for that file; the scan continues | One odd file must not stop an audit |
| 39 | 2026-10-10 | `cobol.copybook_paths` is applied by the linker (candidates under those folders win, in order), not by the COBOL analyzer | Changing the setting re-links without re-analysing cached files |

## Phase 3 decisions

| # | Date | Decision | Reason |
| --- | --- | --- | --- |
| 40 | 2026-10-10 | Dev dependency `jsonschema` validates the SBOM against the vendored CycloneDX 1.5 schemas in tests | Proves acceptance criterion 4 offline; not needed at runtime |
| 41 | 2026-10-10 | Rule packs are YAML in `rules/` (shipped in the wheel as `legacy_audit/_rules`); a team folder (`rules.packs_dir`) replaces rules by id and prepends data entries. Fact rules (`match`) run every scan over the linked facts; text rules (`pattern`) run per file in the cached `patterns` analyzer, with a hash of the patterns in the file-cache key. `rules.disabled` and `rules.severity` are applied when findings are built, also to analyzer findings | Editing a weight, severity or switch needs no re-analysis; editing a pattern re-scans exactly once |
| 42 | 2026-10-10 | Named regex groups starting with `secret` are replaced by `****` before a hit is cached; hits keep at most 120 characters | Credentials never reach the cache, outputs or logs |
| 43 | 2026-10-10 | PostgreSQL grade: Spring Data derived → auto; HQL → auto or review; dynamic or unparsed → manual; a `manual` construct → manual; otherwise sqlglot transpiles from the source dialect, and the grade is review when any listed construct matched (manual if it did not transpile and nothing explains why). The suggested PostgreSQL text is kept only when no non-`valid_in_pg` construct survives in it. Packages, procedures, functions and triggers are manual | Graded with reasons a reviewer can check; sqlglot output is offered only where it really converted the construct |
| 44 | 2026-10-10 | Complexity score = Σ weight × feature / scale (weights, scales and band thresholds in `complexity`). Services: LOC and cyclomatic of their own unit or file plus code files reached within 2 hops, tables, integrations, vendor SQL, fan-out; screens: LOC, fields, fan-out; jobs take their batch-job service's score; a component takes the mean of its services and screens | Deterministic, explainable, re-weightable without re-analysis |
| 45 | 2026-10-10 | Dead-code candidate: a source file (Java, C/C++, Pro*C, COBOL, shell, Perl, Python; not tests or generated) that no service, job, screen, entry point, config or build file reaches over code edges. Java same-package type references, C `sprintf` script commands and HQL entity uses are edges | "Candidate" only: reflection and external callers are invisible, so the agent confirms |
| 46 | 2026-10-10 | Duplication: comment-free token windows of `metrics.duplication_tokens` (50) hashed per file and cached; a window found in two or more places marks its lines duplicated | Language-neutral, cheap to recompute across files every run |
| 47 | 2026-10-10 | Vulnerabilities: reports in `audit-inputs/security/*.json` (Dependency-Check or OSV-Scanner JSON, detected from content) are imported; a tool without an imported report is run if installed, offline (`--noupdate`, `--offline`). Each tool is a coverage row (`dependency-check`, `osv-scanner`); not installed, failed or disabled is a gap, never "no vulnerabilities". Reports match libraries by SHA-1, then package URL, then jar file name; the same CVE from both tools is merged (OSV ids become aliases) | Works on laptops without the tools (teams import CI reports) and with them; a missing check is visible |
| 48 | 2026-10-10 | Recorded reports for tests live in the samples' `audit-inputs/security/` (not `tests/fixtures/`), and the sample tests force both tools "not installed" | They exercise the real input path, and results do not depend on what is installed |
| 49 | 2026-10-10 | Upgrade recommendation, first match wins: end of life (Boot-managed → use-bom, else replace with the named replacement, frontend frameworks → rewrite/remove); `javax.*` → Jakarta EE 11 coordinates; DB drivers → PostgreSQL; Boot-managed (group must be known) → use-bom; vulnerable → lowest version above the current one that fixes every reported CVE (`verify` when a CVE names no fix); else keep. OpenRewrite recipe ids are attached where one applies | Matches the plan's table; targets are data in `dependency-upgrades.yaml`, not looked up online |
| 50 | 2026-10-10 | `jdeps`/`jdeprscan` are opt-in (`security.jdk_tools.enabled: false` by default) | They need a JDK and take seconds per jar on every run |
| 51 | 2026-10-10 | Effort = Σ count × [low, likely, high] person-days per (item, level): services, screens (not partials) and jobs by band, distinct SQL per component by grade, stored code by grade, integrations each, libraries by recommended action. Batch-job services are priced as jobs only. Written to `effort.json` labelled "estimate — weights from config" | Arithmetic on counts with visible weights, not a forecast |
| 52 | 2026-10-10 | SBOM: one CycloneDX 1.5 component per library (bom-ref = library id, purl when group and version are known, SHA-1, scope test → excluded, provided → optional) and one vulnerability entry per CVE with `affects`; serial number derived from application and run id | Validates against the schema; the SBOM is a per-run artefact like `run.json` |
| 53 | 2026-10-10 | Java versions are flagged end of life on the date public updates ended (8: 2019-01, 11+ only before 11); the target is Java 25 either way | Vendor extended support varies by contract; public updates are the common reference |
| 54 | 2026-10-10 | `rules/target-mapping.yaml` is data only, exported as `data/target-mapping.json` for the Copilot agent | The plan gives mapping to the agent, which records exceptions with reasons |
| 55 | 2026-10-10 | SQL built at run time is rebuilt by following the variable that holds the text in source order to the call that runs it, in Java (tree-sitter), C/C++ and Pro*C (tree-sitter-c over the C with `EXEC SQL` blanked), COBOL (tokens of the procedure division plus `VALUE` clauses) and MyBatis/iBATIS. Shared pieces live in `analyzers/dynsql.py`; Java keeps its own node-based evaluator with the same fields | Siva asked for queries built in code to be extracted intelligently in every target language, not only Java; the counting stays deterministic |
| 56 | 2026-10-10 | Code inside if/loop/switch/catch (COBOL `IF`/`EVALUATE`/inline `PERFORM`, ended by a period) is conditional: an append there is an optional fragment, a reassignment there keeps both texts as variants. Up to 5 whole-text variants are kept | Shows what the statement looks like on each path without enumerating every combination |
| 57 | 2026-10-10 | A run-time piece is `?` and is a *value* hole after `=`, a comparison or arithmetic operator, LIKE/BETWEEN/LIMIT/OFFSET/TOP, inside quotes or in an `IN (...)`/`VALUES (...)` list (C numeric `%d`-style conversions are always values), otherwise a *structural* hole. `?` is never reported as a table | Separates injection risk (bind it) from statements whose shape is unknown (manual) |
| 58 | 2026-10-10 | Grading: type `DYNAMIC` or any structural hole → manual; other rebuilt dynamic SQL is graded on its text and each variant, worst wins, at least review. Rule `sql-concatenation` now fires on value holes (high), new rule `sql-runtime-structure` (medium) on structural holes | A rebuilt statement can be converted, but each variant needs a look; unknown structure cannot be converted by a script |
| 59 | 2026-10-10 | A constant, builder start or buffer used only as a fragment is not a statement of its own. A C buffer or string constant that looks like SQL (strict shape) and that no API call or `PREPARE` consumes is reported once with its final text, source `c-string` (call through a wrapper function) | Counts each executed statement once, without losing SQL hidden behind in-house wrappers |
| 60 | 2026-10-10 | A host variable is looked up at the `PREPARE`/`EXECUTE IMMEDIATE` line (last value before it); if it is only filled further down the source (a paragraph or function that runs earlier) its last value is used; if it is never filled in the file the statement stays `DYNAMIC` with one structural hole. DB2 varying-length groups resolve through their level-49 text item, Pro*C `VARCHAR` through `.arr` | Source order is the only order a script can know without running the program; the fallback covers the common "build in one paragraph, prepare in another" layout |
| 61 | 2026-10-10 | `.vscode/` (tasks, debug configurations, settings, recommended extensions) and `scripts/show_sql.py` are committed; every phase adds a section to `docs/validate-in-vscode.md` and the end-of-phase summary says how to validate from VS Code | Siva asked for VS Code validation steps at the end of each phase; tasks have Windows variants since the team uses Windows laptops |
